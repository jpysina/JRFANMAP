# JRFANMAP 产品与技术计划

## 已确定的产品边界

日本全国设备定位仪表，优先 JR 东日本；前台横竖屏观测、用户启动后的锁屏行程记录；允许第三方服务及用户自己的 API Key。默认中文、手机优先、无需账号、轨迹留在本机。名称、配色、多语言和商店发布可在实测后调整。

## 首版交互

监视 → 开始记录 → 设备权限 → 速度/位置/地图 → 锁屏持续采样 → 通知或应用停止 → 本机行程 → 系统文件选择器导出。

底部五个入口：监视、卫星、铁路、行程、设置。深色仪表使用薄荷绿强调有效设备观测；琥珀色标出缺失、过期和异常。横屏将地图与仪表并排。地图为 2D、北向上；手机磁朝向与 GNSS 行驶方向分别命名。没有示例数据冒充实时数据。

## 结构

- `TrackingService`：定位前台服务；GPS/网络 LocationManager、GNSS、气压/旋转矢量/线性加速度、网络可用性。无后台无限启动、无开机自动采集。无定位硬件也能打开界面和地图。
- `AppStore` / StateFlow：进程内设备状态，Compose 生命周期感知订阅。服务生命周期独立于页面和旋转。
- `FixPolicy`：单调时钟判断新鲜度；拒绝明显异常的距离段。GNSS 定位仍新鲜且更准确时，网络点不能覆盖它。
- `TripDatabase`：SQLite 原始定位点与行程；串行 IO 写入，游标流式导出；记录中禁止删除/导出。进程重新创建时关闭未完成行程并标记中断，不默默重启采集。
- `RailMap`：MapLibre 原生渲染、国土地理院本地样式、轨迹和位置 GeoJSON 图层。长时间断点不连线。
- `OfflineMaps`：MapLibre 离线区域资源数据库，限制单区瓦片预算。浏览缓存与显式下载分开。
- `RailRepository`：HTTPS ODPT 查询，应用可见且配置 Key 时每 60 秒刷新，手动刷新亦限频；不重定向 Key、不输出服务端原始错误/含 Key 的 URL；显示来源和时间，空数据=未知。
- `KeyStore`：Android Keystore 的不可导出 AES 密钥 + 本机加密偏好；禁止备份、不将 Key 写入源码。

## 数据与精度

GNSS 对地速度是位置提供方的速度字段，不伪装成轮速或时刻表速度。没有速度字段时显示空值。当前没有隧道惯导；断流时明确显示最后位置，实时速度留空。椭球高不是海拔。传感器缺失时显示空值。加速度仅供观测，不宣称列车牵引加速度。模拟位置明确标记，不计有效里程。

运营方通知、设备位置和用户线路备注互不混用。ODPT 查询成功不保证存在 JR 东日本数据；取得真实授权并验证覆盖前，不宣称已打通实时车次/车速。官方网页入口不进行抓取。

## 下一阶段

1. 真机列车行程：卫星接收、多径、隧道出入、通知停止、长时间锁屏、温升和耗电；离线包完成后飞行模式重启验证。
2. 真实 ODPT 授权验证、各线路覆盖表、数据许可审核；有许可且存在的接口再加车次与车站。
3. 本机历史轨迹回放、GPX、速度/精度时间轴，行程备注落库；地图包管理改为逐区管理与续传。
4. 根据授权线路几何做可解释的铁路匹配；不将匹配结果误标为运营方实时列车位置。
5. 日中英多语言、平板、无障碍、明暗主题；发布签名、隐私政策和商店审查。

## 验收

自动验证覆盖新鲜度、跳点/断点距离策略、ODPT 解析、离线下载预算，执行 APK 构建及 Lint。模拟器用于基础 UI、存储和生命周期验证；不替代实际 GNSS、传感器与厂商省电策略验证。最终实际执行结果另见 VALIDATION.md。
